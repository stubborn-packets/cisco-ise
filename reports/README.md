# reports/

Report-only views of owned desired state. Not observed state (`exports/`). Not a write path.

## policy-evaluation.md

Human-readable evaluation order of the owned Network Access policy sets.

- Generated by scripts/report_policy.py.
- Source is policy/policy-sets.yaml only.
- No ISE connection, no .env, no UUIDs.
- Sets stay disabled. Rank 99 Default is not present.
- Shows each set’s rank, band, state, service, set condition, authentication rules, and authorization rules.

## How to regenerate

From the repo root:

```bash
# Full report
python3.12 scripts/report_policy.py

# Filtered report (example: only wireless sets)
python3.12 scripts/report_policy.py --filter wireless
```

The filtered file is optional and does not have to be committed. The full report is the one kept in the tree.

## What the report deliberately omits

- Rank 99 Default (built-in, not managed).
- Default Network Access.
- NADs (stay in `inventory/`).
- Live GET data (that remains under `exports/`).
- Condition attribute trees (only the CND- name is shown).
- Exception rules (local and global). Those can be added later if needed.
- HTML, color, or collapsible sections (Markdown only for now).

## Filter

`--filter KEYWORD` keeps a set if the keyword appears (case-insensitive) in the set’s name, band, or description. The output file is named `policy-evaluation-KEYWORD.md`.
